# Parser2025 - MiniPascal-Fr Recursive Descent Parser

## Overview
This is a complete implementation of a recursive descent parser for the MiniPascal-Fr language as specified in TP-Comp-2025.

## Files Included

1. **parser2025.py** - Main parser implementation
2. **scanner__1_.py** - Lexical analyzer (scanner)
3. **code.txt** - Sample MiniPascal-Fr program for testing
4. **README.md** - This file

## Features

### Parser Features
- ✓ Complete recursive descent parsing for all MiniPascal-Fr grammar rules
- ✓ Comprehensive error detection and reporting
- ✓ Grammar rule tracking (saves to RULE.txt)
- ✓ Symbol table management (tracks variables and constants)
- ✓ Support for all language constructs:
  - Program structure
  - Constant and variable declarations
  - Arithmetic and boolean expressions
  - Assignment statements
  - Control structures: if-then-else, while, repeat-until, for loops
  - Compound statements

### Output Files
- **RULE.txt** - List of all grammar rules applied during parsing
- **TOKENS.txt** - Tokens generated by the scanner (from scanner)

## Grammar Rules Implemented

The parser implements all rules from the BNF grammar:

```
<ProgrammePascal> ::= programme <NomProgramme> ; <Corps> .
<Corps> ::= [<PartieDéfinitionConstante>][<PartieDéfinitionVariable>] <InstrComp>
<InstrComp> ::= debut <Instruction> {; <Instruction>} fin
<Instruction> ::= <InstructionAffectation> | <InstructionSi> | <InstructionTantque> | ...
... (and all other rules)
```

## Usage

### Basic Usage

```bash
python parser2025.py
```

The parser will:
1. Prompt for a source code filename (default: code.txt)
2. Run the scanner on the code
3. Parse the tokens
4. Display results and any errors
5. Save grammar rules to RULE.txt

### Sample Program Structure

```pascal
programme example1;
constante
    maxval = 100;
variable
    x1, y2 : entier;
    z3 : reel;
debut
    x1 := 5;
    y2 := x1 + 10;
    si y2 > maxval alors
        z3 := 0.0
    sinon
        z3 := y2 * 2.5
fin.
```

### Important Naming Rules

Based on the grammar, identifiers must follow this pattern:
- Start with a letter
- Followed by exactly one digit
- Then any combination of letters and digits

Valid identifiers: `x1`, `a2b`, `test1var`, `z9`
Invalid identifiers: `x`, `abc`, `1x`, `x_y`

## Implementation Details

### Parser Class Structure

```python
class Parser:
    - __init__(tokens)          # Initialize with token list
    - parse()                   # Main parsing entry point
    - programme_pascal()        # Parse program structure
    - corps()                   # Parse program body
    - instruction()             # Parse instructions
    - expression()              # Parse expressions
    ... (one method per grammar rule)
```

### Key Methods

- **match(expected_value, token_type)** - Match and consume token
- **check(expected_value, token_type)** - Check token without consuming
- **error(message)** - Record syntax error
- **add_rule(rule_name)** - Track applied grammar rule

## Error Recovery

The parser attempts basic error recovery:
- Continues parsing after errors when possible
- Skips to synchronization points (semicolons, keywords)
- Reports all errors found, not just the first one

## Known Limitations

1. **Identifier Pattern**: The grammar specifies identifiers as `<letter><digit>{<letter>/<digit>}`, which means they must have at least one digit after the first letter. This is strictly enforced.

2. **Decimal Numbers**: Must have at least 2 digits before the decimal point (e.g., 10.5, not 1.5)

3. **Error Recovery**: Basic synchronization, may not recover optimally from all error scenarios

## Troubleshooting

### "Expected identifier" errors
- Check that identifiers follow the pattern: letter + digit + (letters/digits)*
- Valid: `x1`, `a2test`
- Invalid: `x`, `test`, `1x`

### "Invalid decimal format" errors
- Ensure decimal numbers have at least 2 digits before the decimal point
- Valid: `10.5`, `123.456`
- Invalid: `1.5`, `9.0`

### Parser doesn't start
- Ensure scanner__1_.py is in the same directory
- Check that the source code file exists
- Verify no lexical errors in the source code
